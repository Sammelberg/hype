# starter — Next + own CMS template

This repo is a **starter template**. In a fresh copy, `pnpm init:project` sets name, ports, database and seed identity (see `README.md`); after that, fill in „Project“ below and replace the home page.

Next.js 16 (App Router, React Compiler, typed routes) · own CMS (Drizzle + Postgres, admin on shadcn/ui at `/admin`) · React 19 · TypeScript (strict) · Tailwind CSS v4 · shadcn/ui (radix base, Nova preset) · pnpm.

## Product rules

- **German only, Anrede „Sie“.** All visible text, alt texts, metadata and URLs are German (`/kontakt`, `/suche`, `/ueber-uns`). `<html lang="de">`, `og:locale de_DE`. No i18n layer.
- **Legal pages:** Impressum and Datenschutzerklärung are CMS pages (slugs `impressum`, `datenschutz`, linked in the footer; the admin refuses to delete or unpublish them). Their seeded text carries the owner's details and describes what the site actually does (no cookies, no third parties, contact messages in our own database, deleted after six months and kept in backups two weeks longer, IONOS hosting, server logs kept 14 days); a change to any of that changes the Datenschutzerklärung too. Have both checked before launch.
- **Data sovereignty** is a hard rule — see its section before adding any service, origin, font or asset.

## Code map

Application code lives in `src/` (`@/*` → `src/*`); the root holds configuration, `e2e/` and `scripts/`. Place new code by what it is:

- `src/app/(frontend)/` — routes only: `/` (the CMS page with slug `startseite`), `/[...slug]` (CMS pages by their stored path), `/leistungen`, `/projekte`, `/projekte/[slug]`, `/suche`, `/kontakt`, German `error.tsx`, placeholder monogram icons (`icon.tsx`, `apple-icon.tsx` — swap for designed `icon.png`/`apple-icon.png`), `opengraph-image.tsx` (home), `vorschaubild/[...pfad]` (the drawn share image of every other page; `buildMetadata` points og:image there unless the CMS sets one — the catch-all cannot hold an `opengraph-image`), `next/preview`.
- `src/app/(frontend)/<route>/_components/`, `_lib/` — code used by that one route (`kontakt/_components/contact-form.tsx`, `kontakt/_lib/validation.ts`). Promote it to `src/components/` or `src/lib/` once a second route needs it.
- `src/app/(admin)/` — the admin, with its own root layout and stylesheet (`admin.css`; the site's `globals.css` never loads there): `admin/(auth)/` (login, passwort — no session), `admin/(app)/` (the sections, the sidebar and ⌘K in its layout; `medien/hochladen/route.ts` takes uploads), `admin/_actions/` (one file per aggregate on `authActionClient` / `adminActionClient`), `admin/_components/` (editor shell, section cards and their index, item cards for lists, Lexical editor, preview pane, versions, media picker), `_theme/` (own light/dark switch). `src/app/media/[filename]` serves uploads; `src/app/` also holds `global-error.tsx`, `sitemap.ts`, `robots.ts`; `src/proxy.ts` sends cookie-less admin page requests to the login and hands the rest their path.
- `src/cms/` — the CMS: `db/` (Drizzle schema of the Postgres schema `cms`, pool, migration runner), `migrations/` (drizzle-kit SQL), `content/` (one repository per aggregate: pages, projekte, site-settings, media, redirects, forms, search, versions; `types.ts` holds the zod input schemas and document types, `page-tree.ts` the pure tree logic and the kinds of page, `page-sections.ts` the sections' defaults), `rich-text/` (Lexical document schema, React renderer, plain-text helpers, seed builder, editor converters), `auth/` (argon2id passwords, database sessions, lockout, roles, `requireUser` / `requireRole`), `audit/` (the audit log), `security/` (rate limits, client address), `retention/` (retention periods), `errors.ts` (`CmsError`), `media/` (disk store with sharp variants), `paths.ts` (public URL per routed collection; pure, safe for client components), `revalidate.ts`. Modules under `src/cms/` use relative imports (scripts load them with tsx).
- `src/buero/` — the office (Kunden, Aufträge, Verträge, Rechnungen): `logik/` pure and client-safe with colocated tests (money in cents, status steps and numbers, zod schemas, the §14 check, the XRechnung builder), `daten/` the repositories, `db/schema.ts` the Postgres schema `buero`. Admin screens under `admin/(app)/{kunden,auftraege,vertraege,rechnungen,firma}`, the print view in `admin/(druck)/`.
- `src/data/` — the site's reads: `queries.ts` (every frontend read, React `cache`, draft-aware, one-liners over `src/cms/content/*`), `redirect-or-not-found.ts`.
- `src/components/` — `ui/` shadcn (`pnpm dlx shadcn@latest add <name>`, then adapt), `site/` shared site components (among them the drawn firs of the page headers and valleys, `fir-shapes.ts`), `dev/` dev-only tools (Reticle bridge).
- `src/lib/` — pure helpers with colocated `*.test.ts`: `seo.tsx`, `redirects.ts` (`normalizePath`), `site-nav.ts`, `breadcrumbs.ts`, `curves.ts` (seeded random, smooth paths for the drawn landscapes), `horizon.ts`, `utils.ts` (`cn` from the `cn` package).
- `src/env.ts` (validated env — import `env`, never `process.env`; new variables go into `env.ts` and `.env.example`), `drizzle.config.ts`.

## CMS (own)

- **Documents:** pages (a tree by `parent_id`, the public `path` stored and unique), projekte (`/projekte/[slug]`), one site-settings document (jsonb, `SiteSettingsSchema`: only what every page shares — name, owner, tagline, SEO description, contact e-mail, profile links, the closing invitation), media, redirects, the contact form and its messages, users. Everything lives in the Postgres schema `cms` (the office in `buero`, same migrations: `drizzle.config.ts` lists both schema files); `public` is empty.
- **One place per part of the site:** every text a page shows lives on that page. The pages with a route of their own carry typed `sections` (jsonb, `PageSectionsSchema`, kind by fixed slug via `kindOf`): `startseite` the hero, headings, steps and principles; `leistungen` the five services and the FAQ (the home page reads them there); `projekte` the text without projects; `kontakt` the column beside the form. Their `lead` is the page's own field. The services stay the five hand-drawn glyphs in `src/components/site/service-glyphs.tsx` — the admin edits their copy, not the set. „Website“ in the admin edits only the settings; the contact form's fields are reached from Seiten → Kontakt (`/admin/formular`).
- **Editors** are a column of section cards (`admin/_components/sections.tsx`), one per part of the page in the order the page shows them, with their index in the sticky bar; lists are `ItemCards` (short items in a grid, long ones folded to a line). Each card names a `zone`: working in it scrolls the preview to the element with that `data-cms-zone` and outlines it. A new part of a page gets both: the zone attribute on the site, the card in the editor.
- **Drafts and versions:** live columns are what the site shows; `draft` (jsonb) is the working copy the editor autosaves into; „Veröffentlichen“ moves it into the live columns, writes a row into `versions` and revalidates; „Verwerfen“ clears it; a version restores into the draft. Draft-mode reads (`draftMode()`) merge the draft over the live document, including a changed slug or parent, so the preview shows what publishing would produce.
- **Routed collections:** `src/cms/paths.ts` maps each collection with a frontend route to its path function; rich-text links, redirect targets and the preview resolve through it. A new routed collection needs its table, repository, route, admin section, `revalidateDocument(...)` in its publish action, a place in the sitemap and the search UNION. Carry it end to end with `cms-section`.
- **Home page and routed pages:** the page with slug `startseite` (`HOME_SLUG`) renders at `/`; `/leistungen`, `/projekte` and `/kontakt` are literal routes over their pages. `ROUTED_PATHS` (`page-tree.ts`) keeps all four out of `[...slug]`'s `generateStaticParams`, or the build collides. They and `impressum`, `datenschutz` are `PROTECTED_SLUGS`: not deletable, not unpublishable, slug and place fixed (the repository refuses a change).
- **Page SEO:** without an SEO description a page falls back to its lead or first paragraph; nested pages and projects show a breadcrumb trail (`PageBreadcrumbs`) whose BreadcrumbList JSON-LD mirrors what is visible — keep the two together.
- **Revalidation:** pages are static; publishing calls `revalidateDocument(paths)` (`src/cms/revalidate.ts`: the old and new paths, the sitemap, the layout), settings `revalidateSite()`, redirects and the form their fixed paths.
- **Preview:** the editor's `PreviewPane` is an iframe of `/next/preview?path=…` (needs our session, enables draft mode); after every autosave it posts `cms:refresh` and `PreviewBridge` (`src/components/site/preview-bridge.tsx`) re-renders the page; `cms:focus` scrolls to a zone and outlines it; the bridge answers `cms:ready` after each load so the pane resends the zone; `/next/exit-preview` ends draft mode.
- **Rich text** is Lexical JSON in both directions: `@lexical/react` in the admin (`admin/_components/lexical-editor/`), our own renderer on the site (`src/cms/rich-text/render.tsx`: paragraphs, h2–h4, lists, quotes, rules, links with `next/link` for own paths). Links are stored Payload-style (`fields.url`, `fields.newTab`); `lexical-io.ts` converts for the editor.
- **Search:** Postgres full text with the `german` dictionary on generated `search` columns of pages and projekte (title A, lead and description B, `content_text` C), plus a title `ILIKE` for compounds; `/suche` reads `searchSite`.
- **Redirects** — 308/307 (what Next sends) to a page, a project, a path of this site or an `https://` URL; `from` is normalised (`src/lib/redirects.ts`); no redirect onto itself or into a circle. Publishing a page or project under a new address writes redirects from the old addresses of it and every published page below (`redirectMoves`); a page or project with redirects onto it is not deleted. A page with published pages below is not withdrawn. CMS routes call `redirectOrNotFound(path)` instead of `notFound()`.
- **Contact form** — the form titled „Kontakt“ renders at `/kontakt`; its fields, button and confirmation are edited under `/admin/formular` (from Seiten → Kontakt; the preview shows `/kontakt`). The server action (`kontakt/actions.ts`) validates with `kontakt/_lib/validation.ts` (German messages, honeypot, minimum fill time from a start time the server signs with `FORM_SECRET`, which is why `/kontakt` renders per request), limits messages per address and writes to `form_submissions`; messages are read under `/admin/anfragen` (opening marks them read). There is no public API for messages.
- **Accounts:** own sign-in (`src/cms/auth/`): argon2id from `node:crypto`, sessions in `cms.sessions` behind an HttpOnly cookie (`__Host-` under https), 30 days, all sessions end on a password change. The first account comes from the shell (`pnpm cms:passwort <e-mail> --anlegen`; there is no setup page); further accounts get a temporary password (100 bits) shown once, and until it is replaced every page leads to `/admin/passwort` and every action refuses. No e-mail anywhere.
- **Roles** (`src/cms/auth/roles.ts`): `admin` everything; `redakteur` the site's content (pages, projects, media, Website, form, redirects, inbox). Accounts, the office and the log are `ADMIN_ONLY`. Each admin page checks for itself (`await requireUser()`, `await requireRole("admin")`; layout and page render in parallel, so the layout's check alone lets page code run) and `_lib/pages-check-the-session.test.ts` keeps it so; actions use `authActionClient` / `adminActionClient`; the navigation only hides. The last admin is neither demoted nor deleted.
- **Rate limits** (`src/cms/security/`, `cms.rate_limits`, Postgres only): sign-in per address before argon2, contact messages per address, uploads per user; five wrong passwords lock the account (one atomic UPDATE). The address is the last `X-Forwarded-For` entry, which only holds behind our own proxy (`README.md` → „Эксплуатация на сервере“). Server actions take 2 MB at most; uploads go to their own route (60 MB), outside `proxy.ts`, which buffers only 10 MB.
- **Audit log** (`src/cms/audit/`, `cms.audit_log`): sign-ins, accounts, publishing, deletions, media, redirects, invoices issued and cancelled. Write it in the transaction of the change with `audited(change, entry)` (repositories take a `client` for it). The database numbers, stamps and hash-chains each row and refuses UPDATE/DELETE/TRUNCATE; `/admin/protokoll` (admins) shows it and whether the chain holds. A new kind of entry goes into `AUDIT_ACTIONS`.
- **Errors for people** are `CmsError` (or a subclass): the action client passes their German message on; anything else becomes one generic line.
- **Uploads** live on local disk in `/media` (`MEDIA_DIR`, gitignored; a persistent volume in production), served by `src/app/media/[filename]` with immutable caching and `CSP: sandbox` (`next.config.ts`); raster images only (no SVG), the file's magic bytes decide the type; the original is re-encoded without EXIF/GPS/XMP (`pnpm cms:metadaten-entfernen` cleans older ones), sharp writes 480/960/1920-wide WebP variants, a focal point is kept per image.
- **Schema changes:** edit `src/cms/db/schema.ts`, `pnpm migrate:create <name>` (drizzle-kit writes SQL into `src/cms/migrations/`; read it), `pnpm migrate`. No dev push: every database gets its schema from the migrations, CI included.
- **Seed content:** `pnpm seed` (`scripts/seed-data.ts`) — site settings, the routed pages with their sections (`startseite`, `leistungen`, `projekte`, `kontakt`), the legal pages, `/ueber-uns` with `/ueber-uns/arbeitsweise`, the five `/leistungen/*`, `/branchen/handwerk`, the „Kontakt“ form, redirect `/about` → `/ueber-uns`. No projects (real ones are entered in `/admin`). Idempotent and upserting: it overwrites pages edited in `/admin`, so on a database with real content use `pnpm seed --nur <slug>` for the one page. Local databases only; the only account it creates is the e2e admin, and only when `E2E_ADMIN_PASSWORD` is set (CI). Every new route gets seeded content and an entry in `SEED_PATHS`, which feeds the e2e tests; `scripts/prepare-e2e.ts` creates the e2e account before a run (Playwright `globalSetup`), `scripts/clean-e2e.ts` removes the tests' messages, documents, redirects, probe form fields and account after it.
- **Leaving Payload (2026-09-29):** the content was imported from Payload's tables with ids kept (`pnpm cms:import`, `scripts/import-payload.ts`); it writes the page sections of 2026-09-30 directly (migration `0001_page_sections` moved them on databases that already had the CMS); on the production database run it once after `pnpm migrate`, then `scripts/drop-payload-tables.ts` — both refuse a non-local database without `--force`. Delete both scripts once production is over.

## Büro (office)

Adapted from the neighbouring `boden` project (its invoice core, KoSIT-validated there), reduced to a software business. No new dependency: the E-Rechnung is our own UBL, the PDF is the browser's print of `/admin/druck/rechnungen/[id]`. A ZUGFeRD PDF would need `pdf-lib` and `@react-pdf/renderer` (boden's route) — approval first.

- **Invoices are GoBD documents.** A draft has no number; „Rechnung stellen“ takes the next `RE-YYYY-NNNN` in the same transaction, freezes recipient, issuer and totals as snapshots (`empfaenger`, `verkaeufer`, `summe_*`) and is final: the triggers (migrations `0002_buero`, `0006_gobd_haertung`) refuse any other change, any delete and TRUNCATE; a number series counts by exactly one. The first XRechnung export is archived with its sha256 and handed out unchanged afterwards. Corrections are Stornos (type 384 naming the original). Invoices are kept 8 years (BEG IV); `gobd.db.test.ts` tries every forbidden write. A new trigger or frozen column gets its case there.
- **Retention and backups** (`README.md` → „Эксплуатация на сервере“): `pnpm cms:aufbewahrung` nightly deletes contact messages after six months (`src/cms/retention/`); `scripts/backup/sicherung.sh` (restic; messages in a 14-day group of their own) and `wiederherstellung-test.sh` (restores into a scratch database and compares). A change to either changes the Datenschutzerklärung.
- **Tests never issue into a real database.** `rechnungen.db.test.ts` runs inside a transaction it rolls back; e2e (`admin-buero.spec.ts`) stops at the draft and deletes it; `clean-e2e.ts` sweeps „E2E …“ customers and their drafts.
- **XRechnung 3.0 (UBL)**, `logik/xrechnung.ts`: totals from `logik/geld.ts` (cents, VAT once per rate), §19 Kleinunternehmer as category E with the statutory note. BR-CO-26: without USt-IdNr the Steuernummer goes out once more as BT-29 — the owner's likely shape; keep it in the conformance set. Conformance is measured, not assumed: `KOSIT_URL=http://127.0.0.1:8083 pnpm exec vitest run src/buero/logik/xrechnung.kosit.test.ts` against the pinned validator (`docker run -d --rm -p 127.0.0.1:8083:8081 apps4everything/kosit-validator-xrechnung@sha256:10644cda…`, full digest in the test).
- **One flow around the customer.** Orders, contracts and invoices choose their customer with `KundenWahl` (`admin/_components/buero/kunden-wahl.tsx`): search, or „Neuen Kunden anlegen“ in a short dialog without leaving the document. Choosing an order or contract sets its customer; changing the customer lets go of another customer's order and contract; an invoice takes its position from the order („Aus Auftrag übernehmen“) or the contract's fee. The customer card is the hub: everything of the customer beside it, new documents started from it.
- **A second validator:** Mustang (the port project's check, Java in a container): `pnpm erechnung:proben && pnpm erechnung:pruefen`, or `scripts/pruefe-e-rechnung.sh <file>` for a downloaded XRechnung. It also checks ZUGFeRD PDFs (PDF/A-3), which becomes its main job once a ZUGFeRD PDF exists.
- **What must be on an invoice** is `logik/pflichtangaben.ts`: §14 Abs. 4 UStG blocks issuing, XRechnung's extra fields (IBAN, phone, e-mail) only block the export. The issuer's data live under `/admin/firma`; Steuernummer, IBAN and phone are the owner's to enter, never defaults.

## Styling

- **Every project gets its own design, made fresh.** The template is design-neutral on purpose: shadcn's neutral tokens (light, with a `.dark` set), Geist, Tailwind's default spacing, a plain header and footer. Build the direction from this project's subject and audience with `frontend-design` / `variate`, then record it under „Design direction“ in „Project“. Sources are this brief and material the owner supplies; other projects on this machine and earlier sites stay out of it, so no two sites share a look.
- `src/app/(frontend)/globals.css` holds all tokens; it is imported only by the frontend layout, so the admin stays unstyled by it. A project's palette, radius and spacing rhythm replace the neutral values there; `--container-sm…2xl` stay untouched (shadcn's `max-w-*` depend on them). Colours outside CSS follow it by hand: `themeColor` in `layout.tsx`, `opengraph-image.tsx`, `global-error.tsx`, the icons.
- **Layout:** `page-container` is the page column — up to 1760px (`--container-page`), fluid side gutter 20→80px (`--spacing-gutter`); long text keeps a reading width (`max-w-3xl`, `max-w-prose`). Breakpoints are Tailwind's plus `xs` 480, `3xl` 1920, `4xl` 2560 (`globals.css`); type and the triangle motif step up once more at `3xl`. `.dark` on an element switches everything inside it to the dark token set (the home hero uses it).
- **Home hero:** `_components/mountain-scene.tsx` composes the owner's blocks, back to front: WebGL night sky with moon and mist (`night-sky.ts`), twinkling stars and a random starfall (`starfield.ts`), the mountains and firs, lights rising from the forest (`lights.ts`), the triangle motif (`triangle-motif.tsx`). One GSAP timeline and ticker drive all of it, only while the hero is on screen; reduced motion shows it still. The sky's cloud shader costs more than a 144 Hz frame, so it holds still while the page scrolls and drifts on at rest, on its own clock (no jump after a pause) (Lenis scrolling runs on the main thread and showed every heavy frame). Pure logic of stars, meteors and lights has colocated tests; `e2e/hero.spec.ts` covers the rest.
- **Home services:** `_components/services-strata.tsx` — five wide cards. From lg × 640px up with motion allowed there is no pin and no scrub: as the stage comes within `APPROACH` of its place under the header the page glides onto it at the speed it already has (`glidePageTo`) and holds (`holdPage`, `data-held`; Lenis keeps running and only leaves the wheel alone, since `lenis.stop()` would clip `<html>` and shift the page by the scrollbar's width); the stage listens from the start of the glide, one turn during it already moves one card; each gesture moves exactly one card to the middle (GSAP Observer on wheel and touch, arrow/page keys; input within `QUIET_MS` of the last is the same gesture, so a turn of several notches and a trackpad's glide each count once — the owner's rule: one scroll, one card), one more after the last glides the page on to the next section's top in one glide that follows a new turn but swallows the rest of the turn that started it; one before the first is an ordinary scroll up as far as the hand turned. Nothing pulls on the way up (the owner's call, 2026-10-01): the stage docks only coming down, the page passes it freely going up, and once it lies wholly below the screen the cards return to the first. Code scrolls (`scrollPageTo`, anchors), Home/End and focus leaving the section release it. Each card's ridges shift against each other while it slides (translation only), its ice line draws on arrival. A rail (names, prev/next) jumps, and focus inside a card brings it to the middle. Below that query and with reduced motion the cards are a native sideways track, centred card by card. The valleys come from `valley.ts`: straight-lined ridges with sharp peaks (high far mountains, a middle range, each service's near skyline), the three drawn firs of `fir-shapes.ts` standing on them sized by depth (each fir a `<symbol>`), no copper; `e2e/services.spec.ts` covers docking, one card per turn, a quick turn of several notches, a trackpad glide, leaving and coming back, keys, rail, phone and reduced motion.
- **Motion:** `motion/react` for component/UI motion; GSAP (+ Lenis) only for scroll-driven or timeline sequences; one system per element; always honour `prefers-reduced-motion`; looping motion pauses off-screen.
- **Smooth scroll:** Lenis runs on the whole frontend (`src/components/site/smooth-scroll.tsx`, ticked by GSAP so ScrollTriggers stay in step; off with reduced motion, touch stays native). It glides for a fixed 0.6s ease-out, not Lenis' default lerp, whose tail crawls on in one-pixel steps. Page scrolls from code go through `scrollPageTo`; wheel specs wait for `html.lenis` and poll the position, since Lenis glides to it.
- `baseline-ui` is the default constraint set. Gradients, glow, custom easing or extra animation need an explicit request or a chosen art direction.
- Reuse existing tokens, components and fonts; a new dependency needs approval.

## Data sovereignty (hard rule)

No user, visitor or content data leaves our own infrastructure.

- **Browser:** the CSP in `next.config.ts` is enforcing and same-origin only. Every third-party origin (CDN, fonts, analytics, captcha, embeds, avatars) needs explicit approval; self-host instead. `e2e/data-sovereignty.spec.ts` fails on any request to another host.
- **Server:** no SaaS calls with user or content data. Telemetry is off (`NEXT_TELEMETRY_DISABLED=1`); the CMS is our own code and calls nothing. New services are self-hosted or EU-hosted under our control, after approval.
- **Fonts/assets:** local packages or `public/` only (Geist is bundled) — no `next/font/google`, no remote images.
- **Removed on purpose (US SaaS):** Vercel Analytics/Speed Insights/OTel, Sentry, Upstash, Resend, Cloudflare Turnstile, AI SDK. For a needed capability propose the self-hosted route: analytics → Umami/Plausible, errors → GlitchTip, rate limiting → own Valkey, captcha → honeypot (in place) / ALTCHA, files → MinIO.
- **No e-mail:** nothing is sent. Password resets happen under `/admin/benutzer` (temporary password, handed over in person) or with `pnpm cms:passwort`; form submissions are read in the admin. Login lockout: 5 attempts → 10 min.

## Gotchas

- **Next 16:** `error.tsx`/`global-error.tsx` receive `retry` (not `reset`); `next/image` uses `preload` (not `priority`); `middleware` is now `proxy.ts`; `<html data-scroll-behavior="smooth">` keeps route changes from animating the scroll. Check `node_modules/next/dist/docs/` before using an API from memory.
- **Typed routes:** hrefs and redirect targets from the CMS need `as never`.
- **React Compiler lint:** `Date.now()` and other impure calls are rejected during render — compute them at module scope or in an effect.
- **Migrations:** test one on a scratch database: `createdb` inside the container, `DATABASE_URL=… pnpm migrate && DATABASE_URL=… pnpm seed`, then drop it. drizzle-kit's first migration wrote `CREATE SCHEMA "cms"` while the runner creates the schema for its ledger — keep `IF NOT EXISTS` there.
- **Client components and `src/cms/content/*`:** those modules import the database pool; a client component that imports one pulls `pg` into the browser ("Can't resolve 'dns'"). Client code takes types from `src/cms/content/types.ts`, paths from `src/cms/paths.ts`, tree helpers from `page-tree.ts`. Likewise `src/cms/auth/password.ts` is Node-only; the forms use `password-rules.ts`.
- **Repository tests** (`*.db.test.ts`) run against `DATABASE_URL` from `.env` (vitest loads it) and clean up their `test-` documents.
- **Lexical:** a root without children is refused (`emptyDocument()` holds one paragraph); `useFieldArray` needs `keyName: "key"`, or it overwrites the items' own `id`.
- **Preview cookies:** the preview iframe turns on draft mode for the whole browser; a check of the public site from the same context sees drafts — Playwright uses the `request` fixture for public URLs.
- **e2e in dev:** Reticle overlays can swallow clicks; `e2e/features.spec.ts` and `e2e/_admin.ts` (`hideDevOverlays`) hide them in `beforeEach` — reuse that for new interaction tests.
- **Stale dev SSR:** after a client component is edited, `next dev` can keep serving the old server HTML; a hydration mismatch naming the old `className` means restart it, not a bug. After a schema change (new columns) drizzle in `next dev` can throw "reading 'replace'": restart it too.
- **Removed route:** a stale `.next/types/validator.ts` fails `pnpm typecheck`; delete `.next/types`.
- **e2e and rate limits:** `playwright.config.ts` sends one `X-Forwarded-For` address per run, so the limits of the last run do not carry over; a spec that trips a limit uses its own context and address.
- **Stopping a server:** `~/.claude/skills/parallel-sessions/scripts/stop-own.sh <port>` — it stops only a server running from this project. Never by name pattern (`pkill -f next…`, `killall node`): that also stops the other projects' servers on this machine.
- **`pnpm build` while `next dev` runs** rewrites `.next` and ends the dev server without an error message; start it again afterwards.
- **Skill names:** user-level skills in `~/.claude/skills` shadow project skills of the same name — locally the vendored copies are inactive, so edit a core skill in `~/.claude/skills` and re-vendor. Project variants of a user skill get a suffix (`-de`); the English originals are switched off in `.claude/settings.json` (`skillOverrides`).
- **Several projects side by side:** each has its own app and database port. Playwright reuses whatever server answers on its port — with another project's dev server there, it silently tests the wrong site.
- **graft** keeps its graph in `graft/` (gitignored); a fresh clone needs `graft build`.

## Definition of done

1. `pnpm check` passes.
2. New interactive UI passed `better-accessibility`.
3. The changed flow is verified in the running app (Reticle; scroll and gesture behaviour via `verify-interaction`).
4. `pnpm test:e2e` passes, including data sovereignty; new routes are in `SEED_PATHS`.
