# hype — Hype Agency

Next.js 16 (App Router, React Compiler, typed routes) · own CMS (Drizzle + Postgres, admin on shadcn/ui at `/admin`) · React 19 · TypeScript (strict) · Tailwind CSS v4 · shadcn/ui (radix base, Nova preset) · pnpm.

## Project

Filled in per project. When a task depends on a point still marked _offen_, ask instead of assuming.

- **Site / owner:** Hype Agency — children's party entertainers from Aschaffenburg, serving Rhein-Main. Legal name, form, address, e-mail, phone and § 19 UStG status _offen_ (the seed carries `hallo@example.com`).
- **Purpose and audience:** turn local search traffic into confirmed, prepaid bookings without a phone call; target: 60 % of bookings reach prepayment with no human involved. Main user: a mother of 28–42 on her phone in the evening, 2–6 weeks before the birthday, so every screen is mobile-first; also Kitas and companies (invoice instead of prepayment) and the Ukrainian/Russian-speaking diaspora (host language shown on every character). The booking flow is the one page that earns money; every page carries a „Jetzt buchen“ button.
- **Design direction: „die Einladungskarte“** (chosen 2026-10-04 from three directions; passed over: a Geist-only service look with the price as hero, and a timetable hero on a lemon band). Every party starts with an invitation, so the site speaks like one, and the facts read like a contract:
  - **Palette** (tokens in `globals.css`, hex for images in `src/lib/brand.ts`): Papier `#fbfaff` ground, Tinte `#23194a` ink, Tinte leise `#554c7d` for secondary text, **Himbeere `#c8235f` only for what books** (`primary`), Flieder `#eeeafb` for cards and quiet surfaces (`secondary`), Zitrone `#ffd84a` to mark what is free (`highlight`, always with the words), Minze `#1f7a5c` for „frei“ in text (`frei`).
  - **Type**: the handwritten voice is Shantell Sans (`font-hand`, the `@fontsource-variable/shantell-sans` informal axis, local) for headlines and the invitation card only; everything with numbers, prices, times and terms is Geist, prices `tabular-nums`. German compounds in headlines carry a soft hyphen (`Kinder­geburtstag`), never automatic hyphenation.
  - **The memorable thing is the first screen's invitation card**: its reply slip names the price for the chosen town and the next free Saturday, and on a phone it follows the headline directly so the price is on the first screen. Spend boldness there; keep every other section quiet.
  - **Shapes**: cards `rounded-3xl` with a dashed inner edge where they are an invitation or ticket, the booking button a full pill, inputs `rounded-lg`; a slight tilt only on the invitation card, static.
  - **Not here**: confetti, balloon clip art, rainbow pastels, gradients; joy comes from real photos of real parties.
- **Hosting:** own server in Germany, IONOS or Hetzner _offen_ (the deploy stack fits both); domain _offen_ (`example.de` in `deploy/edge.caddy`). No Vercel-specific features.
- **Deviations from the template defaults below:**
  - **Booking module `src/buchung/`** in its own Postgres schema `buchung` with **its own migration track**: `drizzle.buchung.config.ts` → `src/buchung/migrations`, ledger `buchung.__drizzle_migrations`, `pnpm migrate:create:buchung <name>`; `pnpm migrate` applies kern's track, then this one. Project tables never go into `src/cms/db/schema.ts`: a kern migration pulled later with an older timestamp than ours would be skipped without a word. Characters and city landing pages are tables of this module with routes of their own, not CMS collections.
  - **Booking invariants:** a slot is taken in one transaction that locks the candidate performers (`FOR UPDATE`, in id order) and checks their `belegungen`; the exclusion constraint `belegungen_keine_ueberschneidung` (btree_gist, installed in schema `buchung`) is the backstop. A booking occupies the whole window — travel there, 20 min setup, package and extras, 15 min packing, travel back — not the package's duration. Times are stored UTC and entered/shown Europe/Berlin through `src/buero/logik/kalender.ts`; the last weekends of March and October get tests.
  - **Payment:** online prepayment for private customers through **Mollie** (EU, hosted checkout and webhook; an approved exception to „Data sovereignty“, to be named in the Datenschutzerklärung), invoice through the office for Kitas and companies, behind one adapter interface.
  - **Languages:** German at the root as everywhere; `/uk` and `/ru` are one landing page each with hreflang, no i18n layer, no redirect by language.
  - **Public pages of the module** (`src/app/(frontend)/`): `/figuren` (filters from the address, `?alter=&sprache=&kategorie=`), `/figuren/[slug]`, `/preise`, `/kindergeburtstag/[stadt]` (towns with „Eigene Seite“ only); reads through `src/data/katalog.ts`, static with `revalidate = 300` like the home page, whose invitation card (`_components/einladung.tsx`) shows price and next free Saturday per town. Their texts are in the routes, not CMS pages (a CMS page with the same slug would collide with `[...slug]`). A card that leads to a booking is `EinladungsKarte` (`data-buchen-ziel` keeps the phone's `BuchenLeiste` away while it is on screen); the Figuren row in a scroll scene is `FigurenGalerie`.
  - The plan and the client's spec: `.planning/` (gitignored, local).

## Upstream (kern)

Projects are clones of this repository with `kern` as the git remote `upstream` (push disabled; `pnpm init:project` sets it when the history is kept). The shared core — the CMS (`src/cms/`), the office (`src/buero/`), the admin (`src/app/(admin)/`), auth, security, scripts, deploy and tooling — is changed in `kern` and arrives in a project with `git pull upstream main`. A project changes what is its own: the site's design and routes (`src/app/(frontend)/`, `src/components/site/`, `globals.css`, `src/lib/brand.ts`), content and seed data, its „Project“ section, and modules only it needs. A fix to the core found in a project is made in `kern` first, then pulled.

## Product rules

- **German only, Anrede „Sie“.** All visible text, alt texts, metadata and URLs are German (`/kontakt`, `/suche`, `/ueber-uns`). `<html lang="de">`, `og:locale de_DE`. No i18n layer.
- **Legal pages:** Impressum and Datenschutzerklärung are CMS pages (slugs `impressum`, `datenschutz`, linked in the footer; the admin refuses to delete or unpublish them). Their seeded text carries the owner's details and describes what the site actually does (no cookies, no third parties, contact messages in our own database, deleted after six months and kept in backups two weeks longer, announced by mail through the owner's mailbox, IONOS hosting, server logs kept 14 days); a change to any of that changes the Datenschutzerklärung too. Have both checked before launch.
- **Data sovereignty** is a hard rule — see its section before adding any service, origin, font or asset.

## CMS (own)

- **Documents:** pages (a tree by `parent_id`, the public `path` stored and unique), projekte (`/projekte/[slug]`), one site-settings document (jsonb, `SiteSettingsSchema`: only what every page shares — name, owner, tagline, SEO description, contact e-mail, profile links, the closing invitation), media, redirects, the contact form and its messages, users. Everything lives in the Postgres schema `cms` (the office in `buero`, same migrations: `drizzle.config.ts` lists both schema files); `public` is empty.
- **One place per part of the site:** every text a page shows lives on that page. The pages with a route of their own carry typed `sections` (jsonb, `PageSectionsSchema`, kind by fixed slug via `kindOf`): `startseite` the hero, steps, principles and FAQ (`Faq`, with FAQPage JSON-LD); `projekte` the text without projects; `kontakt` the column beside the form. A kind can also follow from the parent (`BY_PARENT` in `page-tree.ts`, empty in the template: a project's service pages under `/leistungen`, say). `sectionsOf` lays stored sections over the kind's defaults, so a field added later shows its default until the page is edited. Their `lead` is the page's own field. „Website“ in the admin edits only the settings; the contact form's fields are reached from Seiten → Kontakt (`/admin/formular`).
- **Editors** are a column of section cards (`admin/_components/sections.tsx`), one per part of the page in the order the page shows them, with their index in the sticky bar; lists are `ItemCards` (short items in a grid, long ones folded to a line). Each card names a `zone`: working in it scrolls the preview to the element with that `data-cms-zone` and outlines it. A new part of a page gets both: the zone attribute on the site, the card in the editor.
- **Drafts and versions:** live columns are what the site shows; `draft` (jsonb) is the working copy the editor autosaves into; „Veröffentlichen“ moves it into the live columns, writes a row into `versions` and revalidates; „Verwerfen“ clears it; a version restores into the draft. Draft-mode reads (`draftMode()`) merge the draft over the live document, including a changed slug or parent, so the preview shows what publishing would produce.
- **Routed collections:** `src/cms/paths.ts` maps each collection with a frontend route to its path function; rich-text links, redirect targets and the preview resolve through it. A new routed collection needs its table, repository, route, admin section, `revalidateDocument(...)` in its publish action, a place in the sitemap and the search UNION. Carry it end to end with `cms-section`.
- **Home page and routed pages:** the page with slug `startseite` (`HOME_SLUG`) renders at `/`; `/projekte` and `/kontakt` are literal routes over their pages. `ROUTED_PATHS` (`page-tree.ts`) keeps all three out of `[...slug]`'s `generateStaticParams`, or the build collides. They and `impressum`, `datenschutz` are `PROTECTED_SLUGS`: not deletable, not unpublishable, slug and place fixed (the repository refuses a change).
- **Page SEO:** without an SEO description a page falls back to its lead or first paragraph; nested pages and projects show a breadcrumb trail (`PageBreadcrumbs`) whose BreadcrumbList JSON-LD mirrors what is visible — keep the two together.
- **Order and schedule:** pages carry `sort_order` among their siblings (live, not drafted); `siteNav` and every page list follow it, Seiten → Reihenfolge changes it (`ordnePages`), the seed sets `SEED_NAV_ORDER`. A draft can be planned (`publish_at`, `PlanenKnopf`): `pnpm cms:geplant` on the server's timer calls `/next/geplant` (bearer `CRON_SECRET`), which publishes due pages and projects as „Zeitplan“ and revalidates. Media carry an `ordner`; the library searches and shows where an image is the share image (`mediaVerwendung`).
- **Revalidation:** pages are static; publishing calls `revalidateDocument(paths)` (`src/cms/revalidate.ts`: the old and new paths, the sitemap, the layout), settings `revalidateSite()`, redirects and the form their fixed paths.
- **Preview:** the editor's `PreviewPane` is an iframe of `/next/preview?path=…` (needs our session, enables draft mode); after every autosave it posts `cms:refresh` and `PreviewBridge` (`src/components/site/preview-bridge.tsx`) re-renders the page; `cms:focus` scrolls to a zone and outlines it; the bridge answers `cms:ready` after each load so the pane resends the zone; `/next/exit-preview` ends draft mode.
- **Rich text** is Lexical JSON in both directions: `@lexical/react` in the admin (`admin/_components/lexical-editor/`), our own renderer on the site (`src/cms/rich-text/render.tsx`: paragraphs, h2–h4, lists, quotes, rules, links with `next/link` for own paths). Links are stored Payload-style (`fields.url`, `fields.newTab`); `lexical-io.ts` converts for the editor.
- **Search:** Postgres full text with the `german` dictionary on generated `search` columns of pages and projekte (title A, lead and description B, `content_text` C), plus a title `ILIKE` for compounds; `/suche` reads `searchSite`.
- **Redirects** — 308/307 (what Next sends) to a page, a project, a path of this site or an `https://` URL; `from` is normalised (`src/lib/redirects.ts`); no redirect onto itself or into a circle. Publishing a page or project under a new address writes redirects from the old addresses of it and every published page below (`redirectMoves`); a page or project with redirects onto it is not deleted. A page with published pages below is not withdrawn. CMS routes call `redirectOrNotFound(path)` instead of `notFound()`.
- **Contact form** — the form titled „Kontakt“ renders at `/kontakt`; its fields, button and confirmation are edited under `/admin/formular` (from Seiten → Kontakt; the preview shows `/kontakt`). The server action (`kontakt/actions.ts`) validates with `kontakt/_lib/validation.ts` (German messages, honeypot, minimum fill time from a start time the server signs with `FORM_SECRET`, which is why `/kontakt` renders per request), limits messages per address and writes to `form_submissions`; messages are read under `/admin/anfragen` (opening marks them read). There is no public API for messages.
- **Accounts:** own sign-in (`src/cms/auth/`): argon2id from `node:crypto`, sessions in `cms.sessions` behind an HttpOnly cookie (`__Host-` under https), 30 days, all sessions end on a password change. The first account comes from the shell (`pnpm cms:passwort <e-mail> --anlegen`; there is no setup page); further accounts get a temporary password (100 bits) shown once, and until it is replaced every page leads to `/admin/passwort` and every action refuses. „Passwort vergessen“ (`/admin/passwort-vergessen`, offered on the login only once mail is set up) sends a one-time link valid an hour (`cms/auth/reset.ts`: only its sha256 stored, one transaction with the new password, every other link of the account spent, purged nightly); the answer is the same for unknown addresses, and requests are rate-limited per address.
- **Roles** (`src/cms/auth/roles.ts`): `admin` everything; `redakteur` the site's content (pages, projects, media, Website, form, redirects, inbox). Accounts, the office and the log are `ADMIN_ONLY`. Each admin page checks for itself (`await requireUser()`, `await requireRole("admin")`; layout and page render in parallel, so the layout's check alone lets page code run) and `_lib/pages-check-the-session.test.ts` keeps it so; actions use `authActionClient` / `adminActionClient`; the navigation only hides. The last admin is neither demoted nor deleted.
- **Rate limits** (`src/cms/security/`, `cms.rate_limits`, Postgres only): sign-in per address before argon2, contact messages per address, uploads per user; five wrong passwords lock the account (one atomic UPDATE). The address is the last `X-Forwarded-For` entry, which only holds behind our own proxy (`README.md` → „Эксплуатация на сервере“). Server actions take 2 MB at most; uploads go to their own route (60 MB), outside `proxy.ts`, which buffers only 10 MB.
- **Audit log** (`src/cms/audit/`, `cms.audit_log`): sign-ins, accounts, publishing, deletions, media, redirects, invoices issued and cancelled. Write it in the transaction of the change with `audited(change, entry)` (repositories take a `client` for it). The database numbers, stamps and hash-chains each row and refuses UPDATE/DELETE/TRUNCATE; `/admin/protokoll` (admins) shows it and whether the chain holds. A new kind of entry goes into `AUDIT_ACTIONS`.
- **E-mail** goes through the owner's own mailbox over SMTP (`/admin/email-versand`, admins only; no mail server of ours, no mail SaaS): presets for German and EU providers in `lib/email/providers.ts` (Microsoft allows only OAuth and is left out; Gmail only as „Anderer Anbieter“, the owner's own choice), plain SMTP without encryption only to local hosts. Settings in `cms.mail_settings` (one row); the password is sealed with `MAIL_SECRET` (`lib/email/secret.ts`, AES-256-GCM) in a column of its own and never reaches a browser — a new `MAIL_SECRET` means entering it again. `cms/mail/send.ts`: `sendMail` throws a `MailError` in German, `sendSiteMail` only sends once the mailbox is set up and otherwise notes it in the server log; each sent mail is a row of `cms.email_log` („Zuletzt gesendet“), a new kind goes into `EMAIL_KINDS`. A new contact message is announced to `notifyAddress` after the response (`after()`, `cms/mail/anfrage.ts`, Reply-To the sender). Locally and in CI everything lands in Mailpit (`pnpm db:up`, http://localhost:8025); the seed points an unconfigured mailbox at it.
- **Errors for people** are `CmsError` (or a subclass): the action client passes their German message on; anything else becomes one generic line.
- **Uploads** live on local disk in `/media` (`MEDIA_DIR`, gitignored; a persistent volume in production), served by `src/app/media/[filename]` with immutable caching and `CSP: sandbox` (`next.config.ts`); raster images only (no SVG), the file's magic bytes decide the type; the original is re-encoded without EXIF/GPS/XMP (`pnpm cms:metadaten-entfernen` cleans older ones), sharp writes 480/960/1920-wide WebP variants, a focal point is kept per image.
- **Schema changes:** edit `src/cms/db/schema.ts`, `pnpm migrate:create <name>` (drizzle-kit writes SQL into `src/cms/migrations/`; read it), `pnpm migrate`. No dev push: every database gets its schema from the migrations, CI included.
- **Seed content:** `pnpm seed` (`scripts/seed-data.ts`) — site settings, neutral placeholder content („Muster GmbH“): the routed pages with their sections (`startseite`, `projekte`, `kontakt`), the legal pages as drafts with bracketed places for the owner's details, `/ueber-uns` with `/ueber-uns/arbeitsweise`, the „Kontakt“ form, redirect `/about` → `/ueber-uns`. No projects (real ones are entered in `/admin`). Idempotent and upserting: it overwrites pages edited in `/admin`, so on a database with real content use `pnpm seed --nur <slug>` for the one page. Local databases only; the only account it creates is the e2e admin, and only when `E2E_ADMIN_PASSWORD` is set (CI). Every new route gets seeded content and an entry in `SEED_PATHS`, which feeds the e2e tests; `scripts/prepare-e2e.ts` creates the e2e account before a run (Playwright `globalSetup`), `scripts/clean-e2e.ts` removes the tests' messages, documents, redirects, probe form fields and account after it.

## Büro (office)

Adapted from the neighbouring `boden` project (its invoice core, KoSIT-validated there), reduced to a software business. The E-Rechnung is our own UBL (XRechnung) and CII (ZUGFeRD); the PDF is rendered on the server (`src/buero/pdf`, `@react-pdf/renderer` + `pdf-lib`, from `port`).

- **Invoices are GoBD documents.** A draft has no number; „Rechnung stellen“ takes the next `RE-YYYY-NNNN` in the same transaction, freezes recipient, issuer and totals as snapshots (`empfaenger`, `verkaeufer`, `summe_*`) and is final: the triggers (migrations `0002_buero`, `0006_gobd_haertung`) refuse any other change, any delete and TRUNCATE; a number series counts by exactly one. The first XRechnung export is archived with its sha256 and handed out unchanged afterwards; so is the first PDF, in its own table `rechnung_pdfs` (migration `0016`: insert only for an issued invoice, never changed, deleted or emptied), so lists never load its bytes. Corrections are Stornos (type 384 naming the original). Invoices are kept 8 years (BEG IV); `gobd.db.test.ts` tries every forbidden write. A new trigger or frozen column gets its case there.
- **Retention and backups** (`README.md` → „Эксплуатация на сервере“): `pnpm cms:aufbewahrung` nightly deletes contact messages after six months (`src/cms/retention/`); `scripts/backup/sicherung.sh` (restic; messages in a 14-day group of their own) and `wiederherstellung-test.sh` (restores into a scratch database and compares). A change to either changes the Datenschutzerklärung.
- **Tests never issue into a real database.** `rechnungen.db.test.ts` runs inside a transaction it rolls back; e2e (`admin-buero.spec.ts`) stops at the draft and deletes it; `clean-e2e.ts` sweeps „E2E …“ customers and their drafts.
- **XRechnung 3.0 (UBL)**, `logik/xrechnung.ts`: totals from `logik/geld.ts` (cents, VAT once per rate), §19 Kleinunternehmer as category E with the statutory note. BR-CO-26: without USt-IdNr the Steuernummer goes out once more as BT-29 — the owner's likely shape; keep it in the conformance set. Conformance is measured, not assumed: `KOSIT_URL=http://127.0.0.1:8083 pnpm exec vitest run src/buero/logik/xrechnung.kosit.test.ts` against the pinned validator (`docker run -d --rm -p 127.0.0.1:8083:8081 apps4everything/kosit-validator-xrechnung@sha256:10644cda…`, full digest in the test).
- **One flow around the customer.** Orders, contracts and invoices choose their customer with `KundenWahl` (`admin/_components/buero/kunden-wahl.tsx`): search, or „Neuen Kunden anlegen“ in a short dialog without leaving the document. Choosing an order or contract sets its customer; changing the customer lets go of another customer's order and contract; an invoice takes its position from the order („Aus Auftrag übernehmen“) or the contract's fee. The customer card is the hub: everything of the customer beside it, new documents started from it.
- **The invoice PDF** (`pdfFuer` in `daten/rechnungen.ts`, „PDF laden“ → `/admin/rechnungen/[id]/pdf`): one sheet model, `logik/blatt.ts` (`rechnungsBlatt`), feeds both the HTML sheet (print view, the invoice's page, the editor's preview) and the PDF (`pdf/dokument.tsx`), so the two never drift. An issued invoice becomes ZUGFeRD/Factur-X EN 16931 (PDF/A-3b, the CII of `logik/zugferd.ts` embedded as `factur-x.xml`) when its XRechnung data are complete, else plain PDF/A-3b. Fonts are Liberation Sans (OFL, `pdf/schriften/`; PDF/A forbids the unembedded standard-14 faces) and the sRGB profile is `pdf/icc/`; both are read from disk at `process.cwd()`, so `next.config.ts` traces them into the standalone build. react-pdf is imported on demand, only where a PDF is made. The print view stays for paper.
- **A second validator:** Mustang (the port project's check, Java in a container): `pnpm erechnung:proben && pnpm erechnung:pruefen` (an XRechnung and a ZUGFeRD PDF per shape), or `scripts/pruefe-e-rechnung.sh <file>` for a downloaded XRechnung or PDF.
- **What an issued invoice still claims** (`daten/forderungen.ts`, migration 0008): part payments mark it paid once they cover the gross; Mahnungen in three steps (Zahlungserinnerung, 1., 2.) with interest from the start of default (§286: a Mahnung, or 30 days for businesses) at the owner's Basiszinssatz (Firmendaten; never assumed) plus 9/5 points and the 40 € flat fee once for businesses — proposed, editable, then frozen (trigger). Payments are only recorded or removed, never changed; every write is audited.
- **Kinds of invoice:** `abo` drafts per contract period, billed in advance (contracts with „Laufende Rechnungen“, `bereiteAboRechnungenVor`, one draft per period by a unique index); `abschlag` (XRechnung 326) and `schluss`, which on issuing freezes its order's invoices on account with net and VAT per rate (§14 Abs. 5 UStG), states them, deducts them (BT-113) and exports only the rest; its Storno takes them back. Angebote get `AN-YYYY-NNNN` when sent; accepting commissions the order.
- **Calendar** (`/admin/kalender`, month, week, list): the owner's Termine (`buero.termine`, entered as German days and times, stored as instants via `berlinZeitpunkt`) beside every date the office and the site know, read by `daten/kalender.ts` — Wiedervorlagen, due invoices, Mahnfristen, offers' validity, notice dates, contract ends, scheduled publishing. A new dated document belongs in `kalender()`.
- **Tax adviser** (`/admin/steuerberater`): invoice journal and VAT per month as CSV (by issue date, Sollversteuerung) and a DATEV EXTF booking batch whose accounts and numbers live in Firmendaten (defaults SKR03); exports are audited. The adviser should check the DATEV file on the first import.
- **Sending an invoice by e-mail** is an offer, never the only way: „PDF laden“, print and the XRechnung download stay. „Per E-Mail senden“ on an issued invoice appears once „E-Mail-Versand“ is set up (`daten/versand.ts`, plain action `_actions/versand.ts`): a prefilled letter (`logik/rechnung-mail.ts`), the archived PDF via `pdfFuer` (ticked) and the archived XRechnung via `xrechnungFuer` (ticked for businesses and authorities) — the file sent is the file kept —, or instead of the archived PDF one the owner chose (checked by its first bytes, 1.8 MB at most: server actions take 2 MB), at least one attachment. The mail is logged with its target (`email_log.target_type/target_id`, „Versand“ on the invoice), written into the customer's history (`art: email`) and audited (`rechnung.versendet`); the invoice's status does not change.
- **What must be on an invoice** is `logik/pflichtangaben.ts`: §14 Abs. 4 UStG blocks issuing, XRechnung's extra fields (IBAN, phone, e-mail) only block the export. The issuer's data live under `/admin/firma`; Steuernummer, IBAN and phone are the owner's to enter, never defaults.

## Styling

- **Every project gets its own design, made fresh.** The template is design-neutral on purpose: shadcn's neutral tokens (light, with a `.dark` set), Geist, Tailwind's default spacing, a plain header, footer and page header, a placeholder mark (the site name's first letter, `site-mark.tsx`). Build the direction from this project's subject and audience with `frontend-design` / `variate`, then record it under „Design direction“ in „Project“. Sources are this brief and material the owner supplies; other projects on this machine and earlier sites stay out of it, so no two sites share a look.
- The admin has its own tokens in `admin.css`: the same neutral set, light by default, dark by the device or on request (`_theme/`); status colours green done, amber waiting, red faults.
- `src/app/(frontend)/globals.css` holds all tokens; it is imported only by the frontend layout, so the admin stays unstyled by it. A project's palette, radius and spacing rhythm replace the neutral values there; `--container-sm…2xl` stay untouched (shadcn's `max-w-*` depend on them). Colours outside CSS follow it by hand in `src/lib/brand.ts` (icons, share images, `themeColor`, `global-error.tsx`). `muted-foreground` is 0.5, not shadcn's 0.556, which falls under 4.5:1 on `muted` (axe).
- **Layout:** `page-container` is the page column — up to 1760px (`--container-page`), fluid side gutter 20→80px (`--spacing-gutter`); long text keeps a reading width (`max-w-3xl`, `max-w-prose`). Breakpoints are Tailwind's plus `xs` 480, `3xl` 1920, `4xl` 2560 (`globals.css`). `.dark` on an element switches everything inside it to the dark token set.
- **Motion** runs on the compositor; the rules, the effect → tool table, the costly → cheap table and the budget are `docs/motion-architecture.md`, the skill `scroll-motion` before any site animation. Scroll-linked motion is `scrollScene`/`scrollTween` (`src/lib/motion/scene.ts`): written like a GSAP timeline, played by the browser on the page's scroll timeline in the same frame as the scroll (GSAP's own scrub trailed a frame and stuttered in `port`), composited properties only, steps instead of per-frame callbacks; a scene that holds the screen stands in `<StickyStage>` (CSS sticky, never a pin). Arriving once is `<Reveal>` (a CSS transition), text set word by word is `<Worte>` (on the server, never SplitText), loops rest off screen in `<Schleife>` / `useSichtbar`, site links are `<Verweis>` (no prefetch on view). ESLint refuses gsap, lenis, `scrollTrigger` and, in the site's code, `next/link` outside those doors. The h1 and the first screen stand from the first paint; at rest the page does nothing. A stutter is repaired by making the effect cheap, never by removing it. `motion/react` for component/UI motion; one system per element; always honour `prefers-reduced-motion`. The page scrolls natively unless a project renders `<SmoothScroll />` after measuring; page scrolls from code use `window.scrollTo`.
- `baseline-ui` is the default constraint set. Gradients, glow, custom easing or extra animation need an explicit request or a chosen art direction.
- Reuse existing tokens, components and fonts; a new dependency needs approval.

## Data sovereignty (hard rule)

No user, visitor or content data leaves our own infrastructure.

- **Browser:** the CSP in `next.config.ts` is enforcing and same-origin only. Every third-party origin (CDN, fonts, analytics, captcha, embeds, avatars) needs explicit approval; self-host instead. `e2e/data-sovereignty.spec.ts` fails on any request to another host.
- **Server:** no SaaS calls with user or content data. Telemetry is off (`NEXT_TELEMETRY_DISABLED=1`); the CMS is our own code and calls nothing. New services are self-hosted or EU-hosted under our control, after approval.
- **Fonts/assets:** local packages or `public/` only (Geist is bundled) — no `next/font/google`, no remote images.
- **Removed on purpose (US SaaS):** Vercel Analytics/Speed Insights/OTel, Sentry, Upstash, Resend, Cloudflare Turnstile, AI SDK. For a needed capability propose the self-hosted route: analytics → Umami/Plausible, errors → GlitchTip, rate limiting → own Valkey, captcha → honeypot (in place) / ALTCHA, files → MinIO.
- **Mail goes through the owner's own mailbox** (see „E-mail“ under CMS): no mail service of ours or a SaaS; what is sent is stated in the Datenschutzerklärung. Password resets by link once mail is set up, otherwise under `/admin/benutzer` (temporary password, handed over in person) or with `pnpm cms:passwort`. Login lockout: 5 attempts → 10 min.

## Gotchas

- **Next 16:** `error.tsx`/`global-error.tsx` receive `retry` (not `reset`); `next/image` uses `preload` (not `priority`); `middleware` is now `proxy.ts`; `<html data-scroll-behavior="smooth">` keeps route changes from animating the scroll. Check `node_modules/next/dist/docs/` before using an API from memory.
- **Typed routes:** hrefs and redirect targets from the CMS need `as never`.
- **React Compiler lint:** `Date.now()` and other impure calls are rejected during render — compute them at module scope or in an effect.
- **Migrations:** test one on a scratch database: `createdb` inside the container, `DATABASE_URL=… pnpm migrate && DATABASE_URL=… pnpm seed`, then drop it. drizzle-kit's first migration wrote `CREATE SCHEMA "cms"` while the runner creates the schema for its ledger — keep `IF NOT EXISTS` there.
- **Client components and `src/cms/content/*`:** those modules import the database pool; a client component that imports one pulls `pg` into the browser ("Can't resolve 'dns'"). Client code takes types from `src/cms/content/types.ts`, paths from `src/cms/paths.ts`, tree helpers from `page-tree.ts`. Likewise `src/cms/auth/password.ts` is Node-only; the forms use `password-rules.ts`.
- **Repository tests** (`*.db.test.ts`) run against `DATABASE_URL` from `.env` (vitest loads it) and clean up their `test-` documents.
- **Lexical:** a root without children is refused (`emptyDocument()` holds one paragraph); `useFieldArray` needs `keyName: "key"`, or it overwrites the items' own `id`.
- **Preview cookies:** the preview iframe turns on draft mode for the whole browser; a check of the public site from the same context sees drafts — Playwright uses the `request` fixture for public URLs.
- **e2e in dev:** Reticle overlays can swallow clicks; `e2e/features.spec.ts` and `e2e/_admin.ts` (`hideDevOverlays`) hide them in `beforeEach` — reuse that for new interaction tests.
- **Stale dev SSR:** after a client component is edited, `next dev` can keep serving the old server HTML; a hydration mismatch naming the old `className` means restart it, not a bug. After a schema change (new columns) drizzle in `next dev` can throw "reading 'replace'": restart it too.
- **Removed route:** a stale `.next/types/validator.ts` fails `pnpm typecheck`; delete `.next/types`.
- **e2e and rate limits:** `scripts/prepare-e2e.ts` empties `cms.rate_limits` before every run, so the limits of the last run do not carry over; a spec that trips a limit uses its own context with its own `X-Forwarded-For` address (a header for the whole config would also reach dev tools on other origins and fail their CORS).
- **Stopping a server:** `~/.claude/skills/parallel-sessions/scripts/stop-own.sh <port>` — it stops only a server running from this project. Never by name pattern (`pkill -f next…`, `killall node`): that also stops the other projects' servers on this machine.
- **`pnpm build` while `next dev` runs** rewrites `.next` and ends the dev server without an error message; start it again afterwards.
- **Skill names:** user-level skills in `~/.claude/skills` shadow project skills of the same name — locally the vendored copies are inactive, so edit a core skill in `~/.claude/skills` and re-vendor. Project variants of a user skill get a suffix (`-de`); the English originals are switched off in `.claude/settings.json` (`skillOverrides`).
- **Several projects side by side:** each has its own app and database port. Playwright reuses whatever server answers on its port — with another project's dev server there, it silently tests the wrong site.
- **graft** keeps its graph in `graft/` (gitignored); a fresh clone needs `graft build`.

## Definition of done

1. `pnpm check` passes.
2. New interactive UI passed `better-accessibility`.
3. The changed flow is verified in the running app (Reticle; scroll and gesture behaviour via `verify-interaction`).
4. `pnpm test:e2e` passes, including data sovereignty; new routes are in `SEED_PATHS`.
