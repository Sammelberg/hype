# Архитектура движения при прокрутке

Как в `kern` и во всех проектах на нём устроены эффекты прокрутки, чтобы страница не тормозила ни на одном устройстве, в том числе с GSAP и Lenis. Правила здесь — источник истины; агенты работают по скиллу `scroll-motion`, который ссылается на этот документ.

## Откуда это

На сайте `port` (октябрь 2026) секции и фото дёргались при прокрутке на всех устройствах. Разбор показал не одну ошибку, а систему:

- почти каждая секция была сценой прокрутки, и скрипт пересчитывал её на каждом кадре;
- сцены меняли свойства, которые браузер перерисовывает целиком: обрезку (`clip-path`), размытие (`filter`), размеры, цвет, толщину шрифта;
- закрепление секций делал скрипт (`pin` у ScrollTrigger): при обычной прокрутке он переключал секцию на `position: fixed` на кадр позже, и она прыгала в начале и в конце;
- обработчики прокрутки обновляли состояние React на каждом кадре;
- Lenis вёл прокрутку из основного потока: любая задержка скрипта становилась рывком всей страницы;
- ссылки в зоне видимости заранее подгружали свои страницы, около двадцати запросов во время прокрутки.

Первой реакцией было выключить эффекты, и это было ошибкой: владельцу нужны эффекты, а не их отсутствие. Правило отсюда: **эффект не удаляют, его делают дешёвым**.

## Принципы

1. **Одна дверь.** GSAP, ScrollTrigger и Lenis подключаются только в `src/lib/motion/` и `src/components/motion/`. Линтер запрещает импорт в других местах (`eslint.config.mjs`).
2. **Один такт.** Прокрутку ведёт либо браузер, либо Lenis, и тогда Lenis шагает от тикера GSAP и в том же кадре сообщает ScrollTrigger. Других циклов `requestAnimationFrame`, которые читают прокрутку, нет.
3. **Только «лёгкие» свойства.** Всё, что меняется на каждом кадре прокрутки, — это сдвиг, масштаб, поворот, наклон и прозрачность. Их браузер двигает на видеокарте без раскладки и перерисовки. Сцена `scrollScene` другие свойства не принимает: отказ даёт TypeScript, а при обходе типов — сама функция во время выполнения.
4. **Закрепление — CSS.** Сцена, которая держит экран, стоит в `<StickyStage>` (`position: sticky` в высоком держателе). `pin` у ScrollTrigger не используется.
5. **Никакого скрипта на каждом кадре.** Сцена в шагах получает `onStep`, который срабатывает только при смене шага. `onUpdate` с обновлением состояния React на каждом кадре закрыт: и `scrollTrigger`, и `onUpdate` сцене не передать.
6. **Без движения страница полная.** Всё оборачивается в `gsap.matchMedia().add(MOTION, …)`. При «уменьшить движение» сцен нет, а `StickyStage` становится обычной секцией.
7. **Меряют, а не угадывают.** Тест бюджета прокрутки (`e2e/scroll-budget.spec.ts`) проверяет каждую страницу, а жалобу «тормозит» сначала записывают в профиле, потом чинят.

## Как устроено

| Файл                                      | Что делает                                                                                                                   |
| ----------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------- |
| `src/lib/motion/gsap.ts`                  | регистрирует ScrollTrigger и `useGSAP`; отдаёт `gsap`, `useGSAP`, `MOTION`, `refreshScroll`                                  |
| `src/lib/motion/composited.ts`            | список «лёгких» свойств, тип `CompositedVars`, проверка `assertComposited`, `stepAt`                                         |
| `src/lib/motion/scene.ts`                 | `scrollScene(options, build)`: сцена прокрутки на таймлайне, который принимает только «лёгкие» свойства; шаги через `onStep` |
| `src/components/motion/sticky-stage.tsx`  | `<StickyStage length="200svh">`: сцена держит экран средствами CSS                                                           |
| `src/components/motion/smooth-scroll.tsx` | `<SmoothScroll />`: Lenis на такте GSAP, только при точном указателе (мышь, тачпад) и разрешённом движении                   |
| `e2e/scroll-budget.spec.ts`               | бюджет прокрутки на каждой странице из `SEED_PATHS`                                                                          |

Пример сцены — галерея, которая едет вбок, пока секция стоит на месте:

```tsx
"use client";

import { useRef, type ReactNode } from "react";

import { StickyStage } from "@/components/motion/sticky-stage";
import { gsap, MOTION, useGSAP } from "@/lib/motion/gsap";
import { scrollScene } from "@/lib/motion/scene";

export function Galerie({ children }: { children: ReactNode }) {
  const root = useRef<HTMLDivElement>(null);
  useGSAP(
    () => {
      gsap.matchMedia(root.current ?? undefined).add(MOTION, () => {
        const holder = root.current?.querySelector("[data-sticky-stage]");
        const row = root.current?.querySelector<HTMLElement>("[data-reihe]");
        if (!holder || !row) return;
        scrollScene({ trigger: holder }, (scene) =>
          scene.to(row, { x: () => -(row.scrollWidth - window.innerWidth) }),
        );
      });
    },
    { scope: root },
  );
  return (
    <div ref={root}>
      <StickyStage length="250svh">
        <div data-reihe className="flex h-full items-center gap-8">
          {children}
        </div>
      </StickyStage>
    </div>
  );
}
```

Анимации по времени (появление при загрузке, наведение, меню) идут через `motion/react` или `gsap` из `@/lib/motion/gsap` без `scrollTrigger`. Правило о «лёгких» свойствах действует и для них, если они повторяются или идут во время прокрутки.

## Свойства: что дорого и чем заменить

| Эффект                      | Дорого (перерисовка на каждом кадре) | Дёшево (на видеокарте)                                                          |
| --------------------------- | ------------------------------------ | ------------------------------------------------------------------------------- |
| Раскрытие рамки, «шторка»   | `clip-path: inset(…)`                | рамка с `overflow: hidden` и `scale`; внутренний слой с обратным `scale`        |
| Затемнение, «уход назад»    | `filter: brightness()`               | чёрный слой поверх с `opacity`                                                  |
| Размытие при прокрутке      | `filter: blur()`                     | заранее размытая копия (картинка или слой), переход по `opacity`                |
| Рост полосы, прогресс       | `width`, `height`                    | `scaleX` / `scaleY` с `transform-origin`                                        |
| Сдвиг                       | `top`, `left`, `margin`              | `x`, `y`, `xPercent`, `yPercent`                                                |
| Смена цвета, толщины шрифта | `color`, `font-weight`               | два слоя текста, переход по `opacity`                                           |
| Рисование линии             | `stroke-dashoffset` на большой SVG   | маленькая SVG или полоса со `scaleX`; переключение по шагам, не на каждом кадре |
| Тень, свечение              | `box-shadow`                         | слой с тенью, переход по `opacity`                                              |

## Lenis и GSAP

- **Без Lenis** (по умолчанию) прокрутку ведёт браузер в отдельном потоке. Сцена GSAP обновляется на следующем кадре; для «лёгких» свойств это незаметно. Чем меньше работы в основном потоке, тем ровнее.
- **С Lenis** (`<SmoothScroll />` один раз в `(frontend)/layout.tsx`) прокрутка и сцены двигаются в одном кадре. Цена: любая задача скрипта длиннее кадра останавливает всю страницу. Поэтому с Lenis бюджет строже, а правила 3–5 обязательны.
- На сенсорных экранах Lenis не включается: нативную прокрутку пальцем скрипт не повторит.
- `gsap.ticker.lagSmoothing(0)`: медленный кадр не растягивается на следующие.
- Прокрутка из кода — `window.scrollTo` (с Lenis — его `scrollTo`); `scroll-behavior: smooth` на `html` выключен, пока работает Lenis (`globals.css`).

## Медиа и сеть

- Видео вне экрана стоит на паузе (IntersectionObserver), `preload="metadata"`, есть постер. Одновременно играет одно фоновое видео.
- У картинок задан `sizes`, первая на экране — с `preload`, остальные ленивые.
- На длинных страницах ссылки не подгружают страницы заранее (`prefetch={false}`), иначе десятки запросов идут во время прокрутки.
- Повторяющееся движение (бегущая строка, вращение) останавливается вне экрана.

## Проверки

- **TypeScript:** сцена с `clipPath`, `filter`, `width` и подобным не компилируется.
- **ESLint:** запрещает импорт `gsap`, `lenis`, `@gsap/react` вне модуля движения, ключ `scrollTrigger` (значит, и `pin`) и `ScrollTrigger` в коде сайта.
- **Во время выполнения:** `assertComposited` бросает ошибку, если «тяжёлое» свойство пришло в обход типов.
- **e2e `scroll-budget`** (Chromium, процессор замедлен в 4 раза, прокрутка колесом по всей странице):
  - ни одна задача основного потока не длиннее 100 мс;
  - суммарная блокировка меньше 300 мс;
  - ни одна идущая CSS- или WAAPI-анимация не меняет «тяжёлое» свойство.
- **На устройстве:** скилл `verify-interaction` (колесо, тачпад, касание) и запись Performance в Chrome DevTools на телефоне или ноутбуке владельца.

## Когда говорят «тормозит»

1. Узнать страницу, секцию и устройство.
2. Записать профиль (DevTools → Performance, прокрутка через секцию) и найти длинные задачи, перерисовки (Paint) и раскладки (Layout) на каждом кадре.
3. Найти причину в коде: «тяжёлое» свойство, скрипт на каждом кадре, закрепление скриптом, видео, подгрузка.
4. Заменить по таблице выше. Эффект остаётся тем же на вид.
5. Прогнать `scroll-budget` и `verify-interaction`, показать владельцу.

## Чеклист новой сцены

- [ ] Сцена построена через `scrollScene`, при закреплении — внутри `StickyStage`.
- [ ] Обёрнута в `gsap.matchMedia().add(MOTION, …)`; без движения страница полная.
- [ ] Только «лёгкие» свойства; дорогой эффект заменён по таблице.
- [ ] Шаги через `onStep`, состояние React не меняется на каждом кадре.
- [ ] Видео и повторяющееся движение вне экрана на паузе.
- [ ] `pnpm check` и `e2e/scroll-budget.spec.ts` зелёные; поведение проверено через `verify-interaction`.
